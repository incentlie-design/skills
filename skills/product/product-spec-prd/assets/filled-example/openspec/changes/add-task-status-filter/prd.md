# PRD：待办状态筛选（项目扩展）

本 PRD 不是 OpenSpec 原生 artifact。统一运行身份见 [handoff](handoff.json)；原始输入见 [raw-input](../../../raw-input.md)。`artifact_revision: 1`，fixture。

## 目标与边界

用户：只使用本地待办列表、想先处理未完成事项的人。目标：切换到所需状态后看到准确列表，下次打开无需重新选择；偏好存储故障不能阻止当前筛选。

非目标：登录、后端、跨设备同步、关键词搜索、新埋点、改变待办内容/排序。一个 change 只包含状态筛选及其直接恢复路径。

## 用户旅程

| 阶段 | 用户动作与反馈 | 验收 |
| --- | --- | --- |
| 进入 | 无合法偏好时见全部；有合法偏好时恢复选择 | AC-004 |
| 成功 | 选未完成见 t1/t3；选已完成见 t2；选全部见 t1/t2/t3 | AC-001 |
| 空结果 | 全部已完成时选未完成，见“暂无未完成任务”和清除入口 | AC-002 |
| 恢复 | 清除后回全部；零条数据则见“暂无任务”，不伪造记录 | AC-002 |
| 保存失败 | 本次筛选仍生效，见“筛选偏好未保存”；不自动重试 | AC-003 |
| 后续恢复 | 用户再次切换时重新尝试保存；成功后旧错误提示清除 | AC-003 |
| 读取失败 | 仍显示全部，见“无法读取筛选偏好，已显示全部”，之后可正常切换 | AC-004 |

## 约束、风险与未知

只存筛选枚举，不存用户身份或待办正文。保存失败不可回滚当前筛选，不可把失败提示伪装成成功。浏览器存储被清除会失去偏好，这是已接受的本地方案限制。

会改变本次范围/任务分配的未知项：无（仅对本 fixture）；真实项目需核实基线与角色。技术实现是否符合既有 UI 约定，由技术评审确认，未授予实施权限。

## 指标与证据

验收指标：用上表固定数据逐项检查 AC，目标 4/4 满足；当前实测 `not_run`，不能写成通过率。业务收益如“每天少点几次”没有基线，不作数值承诺。后续若要用户研究或线上指标，另行确认，不新增埋点。

## 可选建议与交接

跨设备同步可能减少换设备时重复选择，但需账号/后端和数据策略，明确留在非目标，不生成任务。当前交给 product-reviewer 做独立产品评审，再由协调者按需安排技术/测试规划；创建 PRD 不等于已批准实现。
