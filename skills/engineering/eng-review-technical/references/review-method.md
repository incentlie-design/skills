# 技术方案评审：证据、取舍与交接

## 证据路径

先读 AC 和当前 design，再查看直接相关接口/消费者及历史。可使用有界的 `git diff <base> -- <受影响路径>`、`git log -n 5 -- <路径>`、`git show <真实commit>:<路径>`；替换参数前先确认路径和 commit，不能从示例推断真实历史。无 Git 历史时用可定位版本快照并注明限制。

每条判断区分 **事实**（有具体来源）、**推断**（推理链及不确定性）、**待决**（由谁给什么证据）。不把“没看到错误处理”写成“线上必然宕机”。

| 维度 | 要找的可操作证据 | 阻断门槛 / 最小解除证据 |
| --- | --- | --- |
| 架构与责任 | 从 AC 输入到输出的调用路径、组件 owner、接口/数据不变量、错误和副作用边界 | 已知破坏授权、数据一致性或公共接口为 blocking；说明不变量如何维持或给最小局部修订 |
| 历史一致性 | 当前调用者、ADR/相关提交的原约束，设计偏离点 | 不因“过去如此”阻断；原约束仍成立且新设计违反它才要求修订。缺关键接口历史证据则 blocked，不编造 |
| 方案闭环 | REQ→设计步骤→AC证据；成功/拒绝/超时后状态；必要迁移、回滚和负责人 | 任何范围内 AC 无实现路径，关键失败路径造成不可恢复状态，或迁移无法维持读写兼容则 revise |
| 防扩张 | 每个新增服务/表/依赖/改动路径对应的 AC 或已证实风险 | 无授权的新权限/生产改动直接阻断；无需求的平台化/无关重构要求缩范围，不将其反列为必做 |
| 可实施性和成本 | 现有复用点、最小实施顺序、依赖可用性、可验证的成本依据 | 核心依赖不可用为 blocked；不为预算编造工期。成本超限则给更小方案或请求决策 |

读不到材料的每条发现写明“缺什么会改变哪个判定”。不做无穷补充清单。比如只改阈值，不要求画部署拓扑；改库存幂等键，则必须知道重试请求如何被识别。

## 取舍记录：四个维度都要有决定

| 维度 | 默认决定 | 何时加深 / 何时延期 |
| --- | --- | --- |
| 实现优先 | 复用已有组件，让一条端到端 AC 最快闭合；避免新增运行依赖 | 最小路径违反安全/数据或公共契约时不能以速度为由放行 |
| 技术完整性 | 完成当前 AC 必需的接口、状态、失败、权限与回滚；不追求未来所有能力 | 改 schema/重试语义/权限时补足相关完整性；未来多租户平台或插件化非必要可延期 |
| 深度 | 只追直接依赖和足以改变判定的历史 | 发现具体高影响不确定性才提议有界追加材料；跨全仓审计需新范围，不默默加深 |
| 成本 | 比较实现/维护/运行/评审成本，列已知依据与未知 | 工期未知给相对判断而非精确数字；超过预算交责任人，不无限优化 |

优先序：安全/数据完整性 → 明确目标与 AC → 公共契约/合理架构约束 → 交付和维护成本 → 可选完整性。安全必需不能延期为普通建议；非必需优化不阻断。

至少留下一个能改变方案选择的对比：

| 方案 | AC闭环 / 契约风险 | 实现与运行成本依据 | 结论 |
| --- | --- | --- | --- |
| 现有组件局部修改 | 填受影响不变量和失败处理 | 填实际改动路径/依赖数量或未知 | 选/不选及原因 |
| 有意义替代或不改 | 填与当前目标的差异 | 填引入的维护/运行责任 | 延期或拒绝条件 |

不要为凑两个方案创造夸张替代。当前设计无合理替代时，说明“不改”为什么不满足 AC 即可。

## 判定与复评

严重性和状态不是同一字段：

- `blocking`：安全/数据完整性/不可逆影响，或完成判定所必需的核心缺口。
- `major`：确定导致当前 AC、兼容承诺、可实施性不闭合的缺陷。
- `minor`：不改变本阶段能否进入实施的问题；可放非阻断建议，不能用堆 minor 隐性卡关。

`pass` 要求独立 reviewer、对象可核验、所有当前必需决策闭合且无未解决 blocking/major。它只表示**这个版本的方案可进入实施**，不是实现正确、测试通过或允许发布。

已知必修问题给 `revise`。缺 AC/关键契约、访问权限、真实版本或独立 reviewer 给 `blocked`；混合情况下不能作最终独立判断时优先 blocked，同时完整保留已知缺陷及最小修复。作者可写 self_check/revise 建议，不能冒充独立 review。

任何 finding 的 acceptance 都是“修订后需要看到的证据”，不是已授权的执行动作。建议局部验证可交测试责任人选择层级/预算，不在评审中自动开测。

复评前取得新 revision/摘要；只查原发现的最小修复和它直接改变的接口/风险。未改部分保留来源和复用依据，不能沿用旧 pass 放行新设计。一次复评仍不能闭合时交接，不循环评分。

## Review 模板

沿用 [公共契约](../../../../docs/contracts.md)；以下附加 `tradeoffs`、`limits` 是说明，不替代必需字段。落盘前核对报告写权限。

```yaml
schema_version: 1
run_id: 填运行ID
change_id: 填变更ID
repo: 填真实目标repo
base_commit: 填实际基线commit或uncommitted及原因
artifact_revision: 1 # 从1开始的正整数；不是commit状态
source_artifacts:
  - {path: 填PRD路径, revision: 1} # 替换为来源的实际正整数revision
  - {path: 填design路径, revision: 1}
subject:
  commit: 填实际commit或uncommitted
  content_summary: 填受审内容摘要
  digest_manifest: 填实际SHA-256清单；不存在就注明关键缺口
author: 填作者
reviewer: 填独立评审者；作者自查如实标记
reviewed_revision: 1 # 必须与实际受审design的artifact_revision对应
scope: 填AC、设计章节、影响边界及排除项
status: pass / revise / blocked（选一个）
findings:
  - id: REV-001
    severity: blocking / major / minor（选一个）
    evidence: 填文件/章节/具体行为；推断需标明
    impact: 填影响的AC或不变量
    minimal_fix: 填最小修订或必需证据，不接管实施
    owner: 填责任人
    acceptance: 填修订后可观察解除条件
non_blocking_suggestions: []
tradeoffs:
  selected: 填选定方案及理由
  alternatives: []
  implementation_first: 填最短实现路径及依据
  required_completeness: 填本次不能省略的技术闭环
  review_depth: 填已追踪边界及停止位置
  cost: 填实现/维护/运行成本依据或未知
  deferred: []
limits: [] # 未读材料、未执行测试、不能得出的结论
handoff:
  status: 填pass/revise/blocked
  artifacts: []
  evidence: []
  unresolved: []
  next_owner: 填下一责任人，不自动派发
```

不缺关键证据且无发现时用 `findings: []`。范围内 AC 无映射不能用空数组掩盖。报告完成即停止，不顺手修改方案、实现或测试计划。
