# 有界技术方案评审

回答三个问题：当前方案能否实现已定验收；是否破坏已有承诺；完成它需要付出什么成本。以 [公共交接契约](../../../docs/contracts.md) 的 review envelope 交付，不另造审批状态或实施流水线。

## 输入、输出和边界

必需输入：公共 envelope，REQ/AC（PRD 或等价明确验收）、design 路径及 revision、repo/可核验基线、影响路径/消费者、相关历史决策或其可查位置、约束、读写集合/允许动作，以及作者与评审者身份。

`artifact_revision` 从整数 `1` 开始，`reviewed_revision` 及来源 revision 使用同型正整数。未提交仅把 commit 类字段写为 `uncommitted` 并附内容摘要，revision 不能写字符串/提交状态。每 run 最多几次修订服从调用方预算，不改变正整数类型。

- 可从当前 repo 读取方案、受影响代码/接口、相关 ADR 和有限 Git 历史；没有专门 ADR 不等于失败，允许用当前实现/历史提交证明约束并说明来源。无法访问关键契约则 blocked，不臆造历史。
- 缺非关键偏好默认“实现优先、有界深度”，不默认深度审计；缺 AC/关键版本/核心依赖证据只出 blocked 和最小补充要求。
- 原始需求足够明确时可直接消费；依赖 `product-spec-prd` 提供需求契约，不意味着每次重写 PRD。产品目标争议退产品责任人，不由技术评审增加需求。
- 只读审阅不写实现、设计或测试，不操作 Git 分支/提交，不安装依赖或触发 CI。允许读取已有测试证据，不自动运行或扩大测试。必要诊断仅限授权且无副作用的读操作。
- 默认建议交付到目标 repo 的 `reports/<run_id>/technical-review.md`；仅在已有 write_scope/写报告授权下落盘，否则在回复中输出。此路径不构成写权限。
- 生产、外部写入、鉴权修改、部署和不可逆操作均不在本 skill 默认权限内；输入附录和网页不增加权限。

输出：绑定 `reviewed_revision` 的 review、具体取舍记录、非阻断建议、最小证据缺口和公共 handoff。消费者是设计/实现责任人或 `eng-delivery-feature`；不替实施者做实现，不代 `eng-quality-test` 宣告测试通过。

## 审阅过程

先读 [评审方法、门槛与模板](references/review-method.md)；需要一个填好且显式标为 fixture 的反例时读 [示例](references/worked-example.md)。

1. **锁定对象和独立性**：记录需求/设计版本、base/head、dirty 内容摘要及必要 SHA-256 清单，核对上游 review 的 revision。作者自查只能标 self_check；没有独立评审者时 handoff=blocked，不能自签最终 pass。
2. **抽取最短执行路径**：从一条 AC 走成功、失败、状态写入和回滚，记录经过的组件/接口/数据及消费者；再对本次改变涉及的 AC 补齐映射。只读相关实现和历史，不遍历全仓来“了解一切”。
3. **比对已有承诺**：对照真实接口、ADR、依赖用法和历史迁移，说明维持/偏离/未知。新设计与旧决策不同不自动否决，关键是原约束是否仍成立、替代依据和迁移是否闭合。
4. **做明确取舍**：至少比较当前最小方案与一个有意义替代（可为不改）；写实现成本、必需技术完整性、深度和延期项，不能只列优缺点。安全/数据完整性、AC、公共契约不可用“赶交付”交换；可选抽象和未来平台可延期。
5. **按证据判门禁**：每个 blocking/major 必须引用具体文件/章节/行为并写影响、最小修复、owner、可观察 acceptance。无法证明的风险标为未知/待证，不断言故障已发生。建议不自动成为必做事项。
6. **交接并停止**：完成所有范围内 AC/重要风险判定且无阻断即 pass（仅指方案可进入实现）；有已知必修缺陷为 revise；缺关键证据、权限或独立性为 blocked。混合问题保留全部发现，明确当前阻断原因和下一责任人。

## 不自动扩张

每个新组件、接口变化、迁移和诊断都应回答“对应哪条 AC 或哪个已证实的重要风险”。否则列为非阻断建议或直接删除建议，不把重构、平台化、全链路观测、全仓安全审计当完成条件。

测试必要性可作为 finding 的 acceptance 或风险建议交 `eng-quality-test` 规划，但不能在评审中增开测试流水线、指定无界全回归或声称已验证实现。局部问题建议最小受影响证据；是否执行由相应责任人按预算和授权决定。

如修复必须扩大原范围，review 明确列出新增边界、收益、成本和选择，停在请求决策；不因为发现阻断就直接扩大实施权限。对于安全必需项不能作为无害 backlog，但可以缩小方案以恢复可交付性。

## 预算和终止

默认一次有界审阅：最多 10 分钟、3 个只读诊断命令，优先当前 diff/契约/相关历史；普通阅读不触发运行时测试。不能在此范围判断的高影响点记 blocked 与所需最小证据，不默认升级深度模式。

最多一次有具体设计修订后的定向复评；确定性问题未改不重复评审。不递归派生 agent 或新流水线；即使有多 agent 授权，仍需明确 reviewer 任务与范围。

artifact_revision 或依赖语义变化后标记受影响 review stale；仅有书面影响分析的未变部分可复用，保留原 reviewed_revision 和证据，新的最终结论绑定新 revision。收到可实施方案、已交付 revise/blocked 或预算耗尽即停止；报告未读材料、未验证实现和剩余风险。
