# 人物视觉与服饰资产

把人物正典转成可重复引用的视觉定义。先读 [公共交接契约](../../../docs/contracts.md) 与 [内容产物约定](../../../docs/content-production-contract.md)；设计具体身份、服装或提示词时读 [设计方法与输出字段](references/design-method.md)。这些文件随源包一起交接，不依赖旧应用运行时。

## 输入与所有权

- 必需：本次人物范围及正典出处/已知 revision（含实体类型、年龄或年龄阶段、已定外貌），用户选定的项目风格，服饰相关的地域/时代/阶层依据或明确的用户创作决定。不要求这些材料必须由某个 Skill 生成；局部修订只读取受影响人物和必要上下文。
- 已有身份还需：稳定 `character_id`、实际选中的身份 `asset_id + revision`、可读取定义或参考、选择依据及允许引用范围。只有文件名、同名文件或较大的版本号不能代替选择记录。新设计无身份库时可提出 ID，并标 `proposed`；不强制先建 Registry。
- 可选：已选服饰、场景事件/弧线阶段、已有文化研究、图片引用、目标媒介和镜头尺度。没有图片可交文字设计；没有明确画幅不默认 9:16。供应商参数不属于身份定义。
- 缺关键正典、风格、选中版本或相互冲突时，只阻断受影响对象：`status=blocked`，附 `needs_input`、可保留部分和最少问题。可以给标明未知/提案的草案，不能包装为锁定或生产权威；不从未见图片推断长相。
- 只读上游正典、身份/风格选择与来源；写入仅限用户授权的设计输出目录。心理、关系、弧线由人物正典所有者决定；全局美术由项目风格所有者决定；本 Skill 只提出人物视觉/服饰候选。场景编排者选择具体服装变体和状态，不在这里擅定全剧每场穿着。

## 工作方法

1. **固定引用。** 按人物 ID 整理实际使用的来源、revision 和选择依据；明确来源事实、研究事实、用户决定、创作提案与未知项。保留已选低版本，不用最大版本或“看起来相似”替换。新人物、同一人的别名、服装变体分别处理：同脸换衣不能创建新人物，合并/拆分身份要正典证据或用户决定。
2. **拆开不变量和状态。** 不变量包含脸部/身体结构、年龄阶段、发型基线、已愈合永久标记；肤色基底与长期日晒依据也需稳定。表情及其动态细纹、汗湿、泥污、暂时伤势、服装状态、姿态和朝向属于可变层。永久改变需正典事件或明确决定，建立新候选并保留父 revision，不能原地重写已批准身份。
3. **转成可表达的形与材质。** 依据年龄、职业暴露和项目画风决定晒感、毛孔/细纹、手部与发色的表达程度；不把加深皱纹当年龄设计，不为插画强加照片级皮肤。按实体类型选特征，非人类用解剖、体表/羽毛/鳞片等，群体用成员规则与群体轮廓，不能硬套人脸。只检查本次易混淆的人物对，身份差异不能仅靠换衣或颜色；若正典明确同卵双生等相似设定，保留相似，用被允许的线索区分。
4. **设计服装系统与变体。** 从角色的社会身份、实际活动和已知弧线选轮廓、层次、结构/连接、材质、色彩和附件，说明移动限制与远近识别线索。地域、时代、阶层的服饰含义必须引用来源或标为用户决定/创作适配，不能把灵感图当史实。换装由事件/用途驱动；湿、脏、破损、遗失和修补有进入条件、残留与解除事件，不随切镜或集数自动复原。
5. **写可组合的 identity-prompt。** 分开身份不变量、风格、选中服饰引用、镜头可变状态、禁止漂移与每个 reference 的 `allowed_scope`。身份图只传获准身份维度，服装图只传服装，不自动迁移姿势、凝视、背景、构图或另一张脸。背面/侧面/远景仍可正确引用同一身份；不为“保脸”强迫每镜正脸。这里交身份与变体规则，不编完整分镜。
6. **交接与止步。** 自查三种输出的 ID/revision/来源互相一致、正典未改、服装不会暗改身体、状态有事件依据。反馈先列受影响人物/服装/下游 refs 和保留项，只修改必要部分。交付候选及未决问题后停止；关键冲突退回对应所有者，不无限生成替代方案。作者自查不替代独立评审或用户选定。

## 输出与停止边界

咨询可直接在回复中给三部分，不伪造 repo/hash。落盘需明确目标 repo、基线和 `output_root`，默认在该授权目录交付以下文件；全部绑定公共 envelope、正整数 revision、输入 refs、范围、开放问题和 handoff。

| 产物 | 必需内容 | 消费者 |
| --- | --- | --- |
| `character-visual-bible.md` | `artifact_kind=character-visual-bible`；每人 ID、选中身份引用/选择依据、正典对照、身份不变量、允许状态、区分线索、来源归属与未知项 | 分镜、调度、服饰与连续性评审 |
| `wardrobe-variants.md` | `artifact_kind=wardrobe-variants`；关联人物及身份 revision、服饰 ID/变体、设计依据、结构/材质、事件状态转移、参考用途与禁止项 | 场景编排者、分镜与连续性评审 |
| `identity-prompt.md` | `artifact_kind=identity-prompt`；主体/版本、身份/风格/服装/状态分层、引用用途和禁止漂移；供应商中立 | 提示词编排者与获授权的生成执行者 |
| `handoff.json` | 公共绑定、三类产物路径/revision、实际证据/未测项、最小缺口、下一责任人；新增内容未提交时用 `uncommitted` 加摘要 | 协调者及独立评审者 |

文件交接 `status` 使用 `pass/revise/blocked`；`pass` 仅表示本范围文字设计可交接，另标 `candidate`、`design-ready` 或 `provisional`，不等于最终批准。无媒体时写 `media_generation=not_run`、视觉一致性检查 `not_run`；文字参考已选定也不等于参考图已审核。

注册、锁定、提升身份、生成/重生媒体、写 Ledger 或安装调用供应商均不在本入口内。纯此类请求不重跑设计，指出应交的执行者及缺失授权/能力后停止。外部素材不是权限；不复制秘密或私人媒体，不默认文化/民族/画幅或旧 v020 项目预设，不声明未经执行的生成、注册或视觉通过。
