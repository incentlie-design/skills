# 视觉风格与世界场景

把世界规则转成可复用的视觉决策，交付 `visual-style-bible` 与 `location-prop-definitions` 候选。可只做本次需要的风格、地点/道具或光色增量，不自动扩成全剧资产库。

## 输入、归属与边界

- 必需：目标与范围、可读的原文/brief 或明确允许原创的说明；已有项目还需调用方选定的风格及相关地点/道具版本。局部光色设计需时段/天气、故事变化和相关材质；已有调度/摄影方案只读消费。
- 可选：媒介与画幅、文化研究、视觉参考、角色/服饰定义、受影响下游列表。未给画幅就保持未定；没有真实文化对应的原创世界可声明文化考据不适用，附理由。
- 缺口：只缺可逆细节时做标明 `proposed` 的有限补全；选定风格冲突、关键世界规则不明或历史真实性无证据时，阻断相关定稿，返回 `status=blocked`、`needs_input` 和最小缺口。不因用户催定稿而把猜测写成权威。
- 只读来源与已有批准产物；写入仅限用户授权目标工作区内的新候选。无落盘目标则在回复中交付，不伪造 repo/commit。不能覆盖批准版本、改 Registry/当前版本指针、调用媒体模型或自签批准。只要求文件交接，不强制调用其他专业 Skill。

采用[公共交接契约](../../../docs/contracts.md)和[内容产物契约](../../../docs/content-production-contract.md)。落盘运行绑定公共 envelope；路径相对目标 repo。迁移本 Skill 时须携带这两份公共文档。

## 方法

1. **定一个风格来源。** 记录用户实际选定的 ref/revision/状态，不按最新文件或同名认定权威。区分原著事实、研究事实、用户决定、创作推断与未知。已有风格是当前约束；首次创建只提出候选。参考图注明可借用的维度，不把其中的脸、姿势或服饰混成项目正典。
2. **把风格写成因果。** 说明呈现方式、材料表现、光源规则、主色/强调色及允许变化如何服务叙事。奇幻强度须来自世界机制、触发条件和可见结果；“银树”一词不能推出自发光。不要用“电影级”代替可执行规则。具体风格/光色任务读[设计方法：风格、材料和光色](references/design-method.md#风格与材料)。
3. **固定可复用空间与物件。** 复用稳定 `location_id/prop_id`；新 ID 标 `proposed`。地点定义方位、分区、出入口、固定地标、尺度与连接；道具定义外形、材料、功能、握持点及允许状态。把不变量与时段/天气/持有者/位置等本次状态分开，不能把未给出的动作编成已发生事实。做实体定义时读[地点与道具](references/design-method.md#地点与道具)。
4. **在权威内做光色变化。** 每次变化连到故事/时段依据，写光源动机、方向和软硬、明暗关注层级、颜色关系、皮肤与布/木/金属等实际材料的反应、连续性进出。梦境/奇幻转换保留现实锚点。只给语义设计，不编测得的照度、色温或曝光，不替摄影改机位、不替人物设计改身份。
5. **交接最小变更。** 给一个有理由的推荐；只有影响叙事且证据无法消解的分歧才保留至多两个备选。列保留项、变更项、受影响 refs/revisions 与待下游复核项。关键风格变化退回其选择责任人，不在地点卡里偷偷重写全局规则。

## 交付与停止

落盘默认在获准的输出目录交付 `visual-style-bible.md`、`location-prop-definitions.md` 及 `handoff.json`；只做局部任务时仅交付对应增量并引用原版本，不创建空壳文件。每份产物声明 `artifact_kind`、目标/范围、实际 `input_refs`（定位+已知 revision，未知明确标出）、正整数 `artifact_revision`、开放问题、消费者和 handoff。

| 产物 | 下游必须能读到 |
| --- | --- |
| `visual-style-bible` | 选定来源/候选状态；呈现、皮肤/环境/服饰材料、动机光、色彩和奇幻规则；不变量、允许变体、禁止漂移及依据。供人物视觉、地点、分镜/插画/游戏美术消费。 |
| `location-prop-definitions` | 同一风格 ref/revision；地点空间与连接、固定地标、材料和允许变体；道具身份、尺度、功能、握持/状态转换、已知持有与位置；来源/提案分界。供调度、摄影、分镜、资产执行和连续性消费。 |
| `handoff` | `status=pass/revise/blocked`、产物 refs、证据、缺口和下一责任人；`pass` 仅表示设计可交接。用 `design-ready` 或 `provisional` 描述设计就绪度，媒体执行记 `not_run`，不表示已生成、已注册、已锁定或通过独立审查。 |

自查一次：两个产物风格来源一致；奇幻机制与材质/灯光不矛盾；空间和道具状态可被下游重建；历史事实有来源；未越权。满足范围内设计交接即停，问题只做一次有证据的定向修正；仍缺输入则交回责任人。纯生成、注册、镜头设计或成片检验请求，说明边界并交给相应执行者，不启动另一套生产流程。
