# 计划与影响记录

在落盘或交接给专业 owner 时读取；有反馈再使用后半段。以下为内容记录，不是新运行时协议。沿用 [公共 envelope 与状态](../../../../docs/contracts.md) 和 [内容引用规则](../../../../docs/content-production-contract.md)，不重复应用 Registry schema。

## 四类产物

默认在获准的本次输出目录写 `production-plan.md`、`skill-dispatches.json`、`revision-impact.md`、`handoff.json`；咨询可在回复中按四类组织，不必造文件。每份记录保留公共 envelope（已知 repo/base_commit、正整数 artifact_revision 等）和 artifact_kind、目标/范围、实际 input refs、开放问题、消费者与 handoff。未提交 commit 类字段用 uncommitted 加内容摘要，不把 HEAD 当新内容版本。

| 产物 | 至少要能回答的问题 |
| --- | --- |
| production-plan | 本次要到哪个前置交接点？有哪些真实已有物、缺口和非目标？当前全剧context索引与每集读取哪个revision？节点/依赖理由/下一步是什么？哪些不调、为何复用？预算/人工决定/结束条件是什么？ |
| skill-dispatches | 每项 task_id、能力或待接角色、owner、episode/scope、depends_on、读入路径与revision、write_scope、输出、AC、允许动作/成本预算/重试停止条件、公共任务生命周期状态；缺 owner/必要输入/许可保持 draft或blocked，不标ready |
| revision-impact | 反馈原话/出处、当前选中版本、预期差异、修改与保留项、引用传播、受影响评审、候选父版本、待决策者；无反馈用有理由的not_applicable |
| handoff | 公共 status=pass/revise/blocked、本次四类产物路径/revision、证据及其局限、未解决问题、下一owner/最小动作/解除条件；声明计划与媒体执行的边界 |

节点验收应对应下游能消费的文件/引用，例如“剧本候选包含 scene/line/speaker 与 canon-r2 来源，供分镜读取”，不能写“调用完成”或“JSON合法”作为唯一内容成功条件。

对每条关键证据记 `ref + revision + 来源类型 + 支持范围 + 局限`。例如用户抄录“approved”是用户报告，无法证明实际审批对象/版本；内容检查、schema检查、试听/渲染各有不同支持范围。仅在真实产物与要求的执行/评审证据吻合时记录完成。NOT_APPLICABLE写理由，not_run保留尚未执行，不能代替通过。

## DAG 的最小构造

1. 以目标交接物为终点列必需输入，向前补其缺口；来源导入仅建立只读引用和可用性，不擅自复制完整原著或媒体。
2. 用有版本的产物消费关系连边。资源/权限/owner未就绪是外部阻断，注明解除条件；不要画成已执行节点。一个已有可复用产物不必对应一次新调用。
3. 对每个 episode 建一个上下文切片：选中全剧snapshot、相关正典/角色知识/伏笔目标、前集交接、当前资产refs与禁止漂移项。图中明确“EPn交接并回收变化→主控确认快照→EPn+1读取该快照”。确认未必是人审批；主控依据既有授权和实际结果完成记录。
4. 用拓扑顺序核对无环、无缺失依赖；同一产物不能由两个writer同时修改。后续集尚无输入版本时写待绑定条件，不能伪填“最新”。
5. 将计划停点与后续生产区分：provider-free包可包含剧本/分镜/声音与剪辑设计及refs，不包含未经执行的媒体事实。目标需要精确timing或音画质量结论时，该部分等实际媒体和复核，不逼迫其它设计先付费执行。

## 反馈影响分析

影响链先从反馈对象出发，按实际refs向下游走，直到消费者确实不受该差异影响或出现需要确认的缺口。别只按文件名/整集大小判影响。

| 差异 | 先核对 | 常见最小传播；均需实际映射佐证 |
| --- | --- | --- |
| 台词文本改变 | line ID、speaker、人物动机/知识、前后回应、拆集目标是否仍成立 | 该line的声音表演与字幕→绑定shot的时长/口型/剪辑；不自动改声音身份或人物外观 |
| 身份/场景/道具状态改变 | entity与选中asset revision、出现位置/时序、是否触及全剧权威 | 引用该状态的shot/后集；先判断可否局部变体，不能将局部对象自动升级成全剧资产 |
| 停顿/节奏改变 | 实际音频timing还是估计、同步关系与叙事效果 | retime相关区间与字幕/声音层，不因节奏反馈默认重写故事或重生图像 |
| 因果/结局改变 | 伏笔与回收、人物弧线、前集事实及用户保留项 | 列具体受影响集与重大取舍，未确定前只阻断相关修订，保留既有批准版 |

用一个紧凑表交代 `对象@旧revision → change/retain/revalidate/unknown → 理由与实际ref → 候选revision或待绑定 → stale证据 → owner`。候选ID/revision为拟议时标 proposed；revision数字不证明已创建。

- **change**：本次最小差异，要给父版本和输出候选；不是就地覆写。
- **retain**：明确同一依赖版本、反馈未触及其语义/状态；不能仅写“应该无影响”。
- **revalidate**：依赖已变化但未证明必须重做；派发最小复核，避免把所有待复核项都变成再生成任务。
- **unknown**：缺引用、选中版本或执行证据；列最小补充，不猜保留/通过。

交给用户/主控的简短反馈说明包含理解的变化、保持不变、实际已做与仍拟议的动作、预计成本依据或未知项、受影响下游及回退来源。没有调用就写“已完成影响分析/拟派发”，不写“已开始生产”。如果新台词与“保持结局/动机”冲突，把取舍交给创作owner，不擅自改全剧来消除冲突。

重做或复核回来后读取新产物而非只读状态标签；提高本次 artifact_revision，更新受影响边及证据新鲜度。原有批准引用不移动；权威提升由主应用或获授权owner决定。
