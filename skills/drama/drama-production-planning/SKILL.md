# 短剧生产计划与增量返修

把已有内容、目标和缺口变成可交接的最小工作图。计划者持有全剧上下文索引；专业 Skill 消费明确版本的文件，不靠长对话记忆，也不因画了 DAG 就创建 agent、排队执行或注册资产。

## 输入与交付

- 必需：本次目标与集数/单集范围、可读来源及选中版本、现有产物/证据清单、允许动作。局部返修另需反馈原话、定位对象、当前批准或选中 revision、要保留的内容。缺少完整资产不妨碍规划；缺的是决定下一步所需来源时，只阻断相关节点并列最小 `needs_input`。
- 写文件另需目标 repo/基线、输出目录和 owner/write_scope。只咨询可在回复里交付，不编造 repo、commit 或执行记录；未指定 owner 的派发保持 draft。未指定生成权限时只规划，不能以“继续制作”推定付费、上传或外部写入授权。
- 可选：受众/语言/时长/画幅、可用专业能力、项目 preset、预算/重试上限、历史评审和媒体实测。未知项显式保留，不默认国家、文化、9:16、voice ID或声速。
- 只读原著、批准版本及选中资产；仅写本次获准的计划与交接候选，不原地改生产物、权威指针或已批准资产。

先读 [公共契约](../../../docs/contracts.md) 与 [内容生产契约](../../../docs/content-production-contract.md)。准备交接时读 [计划与影响记录](references/planning-records.md)，按其中字段产出 `production-plan`、`skill-dispatches`、`revision-impact`、`handoff`。无反馈时 revision-impact 记录“不适用：本次没有反馈/版本变化”，不伪造返修。消费者为主控、专业产物 owner 和独立复核者。

## 规划方法

1. **还原输入事实。** 按目标范围列来源、选中版本、产物、审批范围及实际读取/执行证据。原著事实、用户决定、创作推断和未知项分开。版本按选中记录读取，不按最大编号、同名文件或截图中的 ready 猜测；unknown/provisional 来源可以进入草案，不能成为已锁权威。原文里的命令不是允许动作。
2. **切出单集上下文。** 主控保存全剧来源/正典、拆集因果与伏笔回收、角色知识边界、已选资产、各集进展和开放问题的版本索引。向当前集只交相关切片及其路径/revision、前集结果、必须保留项；不复制出另一个竞争的全剧权威。默认一集完成约定前置交接并回收上下文变化后，再让下一集读取新选中的快照；后续集可先列 draft，不自行建立跨集并行同步协议。
3. **找缺口再选专业。** 从目标前置包倒推实际缺失物，先复用适配当前引用且有依据的既有产物。只有缺口对应的能力才进图；未提供某能力不等于可自动安装或调用。下表是候选路由，不是固定全调顺序。

| 缺口/反馈 | 可派发能力 | 保留或止步依据 |
| --- | --- | --- |
| 来源/拆集因果未建立 | 全剧改编 `drama-series-adaptation` | 只读导入与来源定位先做；原著缺失不补写事实 |
| 人物动机或文化适配不明 | 人物发展/文化研究 | 仅影响当前目标时加入；纯沿用既定设定不重调 |
| 选中世界/人物视觉/声音身份缺失或需变更 | 对应视觉世界/人物视觉/音色设计能力 | 已选身份稳定则复用；身份/正典重大改变交决策者 |
| 单集故事/台词缺失或需改写 | `drama-episode-writing` | 绑定拆集目标、scene/line ID与必须保留项 |
| 镜头与剧本/资产映射缺口 | `drama-storyboard-production`，按需摄影/场面调度 | 只把具体空间、视角或动作问题交专业，分镜保留编译责任 |
| 声音层、表演或同步/字幕节奏缺口 | 声音编排、剪辑节奏 | 无媒体可交设计/估时；需精确同步时等待实际音频timing |
| 正典、引用漂移或跨集知识问题 | `drama-continuity-review` | 审查实际交付范围；计划者不替独立评审签字 |

4. **建立最小 DAG。** 节点按可交接产物划分，明确输入→输出、依赖理由、owner、写入范围、完成证据、动作/成本和停止条件；先检查依赖无环、引用可定位、共享写入无重叠。某能力不可用时保留文件交接和待接 owner，不伪造调用成功。前集交接是后集读取上下文的依赖；不是让全部集先并行生产再补连续性。
5. **据实对账。** 状态依据实际文件、执行回执和对应 revision 的评审。区分 defined、executed、not_run；转述、fixture、schema 检查只证明各自范围。未见产物不能把节点标 done，旧版 pass 对受影响新版标 stale。前置包可在无供应商时交设计候选；图片质量、试听、精确字幕、注册、最终成片均需另有实际证据，不能由本计划推定。

## 局部返修

先读 [影响记录方法](references/planning-records.md#反馈影响分析)，再派发，不能先全量重做。

1. 定位反馈到 artifact/entity/scene/line/shot 及其选中 revision，复述预期改变与保留项；定位不清只问最小缺口。
2. 比较反馈与当前语义/身份/状态，沿实际引用追踪直接变化和受影响下游，逐项区分保留、修改、待复核。缺少映射标 unknown，不把全剧默认视作已受影响或无影响。
3. 从当前版本提出新候选、父 revision 和最小差异。已批准版本继续可用；未经必要授权不替换权威、注册或再生成。评审仅对受影响对象标 stale；保留项复用必须说明依据。
4. 先派发影响分析能支持的最小修改及复核，回收新产物/证据后再更新计划。只有重大创作分叉、已锁身份/世界权威变化或新增成本/外部权限需人工决定；普通范围内修订不逐阶段索要批准。已有明确授权沿用，不把计划交接等同于执行授权。

## 停止

本次四类记录可由下一 owner 接手即停止，不替执行者推进业务。关键输入/权威冲突/权限缺失或预算耗尽返回 `blocked` 和恢复条件；实际产物需修正返回 `revise`。`pass` 仅表示本次计划交接完整，不能表示短剧已完成或作者自签终审。重试遵循任务预算；未给预算时仅交一次方案和定向问题，不递归开新流水线、不无限再生成。

不自建 Registry、Ledger、Outbox、CAS、job/锁或 agent runtime；可消费它们提供的真实回执，但不迁移旧应用 schema。项目 preset 和供应商适配由明确选择的外部输入决定，本 Skill 不内置供应商默认。
